hits/n (%, Wilson 95% CI). Read [RISKS.md](../RISKS.md) first: the caveats at the end of this page

## Headline: per-run recall

Per-run recall is the headline metric (SPEC §10): each review is scored on its own. Cells show
the run counts, then the per-bug mean catch rate and its 95% CI with the bug as the unit. The % is
not hits ÷ runs: it equals that only when every bug has the same number of usable runs.

| level | cerebras qwen-3.8-27b | groq gpt-oss-120b |
|---|---|---|
| L0 | 69/69 runs (100%, 86–100) | 58/69 runs (84%, 65–94) |
| L1 | 66/69 runs (96%, 79–99) | 51/68 runs (74%, 54–87) |
| L2 | 69/69 runs (100%, 86–100) | 53/69 runs (77%, 57–89) |

Intervals are Wilson 95% with **the bug as the unit (n = 23)**: a bug's k = 3 runs are correlated
(cerebras's are byte-identical at temperature 0), so an interval over 69 runs would overstate the
evidence about √3-fold.

**Comparing the two models (corrected 2026-11-26).** Both models are scored on the same 23 bugs, so
the right comparison is paired: the per-bug difference in catch rate. (Earlier versions of this
report compared each model's own interval, first too loosely, then too strictly.) Paired, at L0,
gpt-oss-120b minus qwen-3.8-27b is −16 points (95% CI −29 to −3); qwen catches more on 6 bugs and
gpt-oss on none. So on v0.1 **qwen-3.8-27b catches more planted bugs than gpt-oss-120b**, with
caveats: 23 mostly synthetic bugs, several comparisons, and most of gpt-oss-120b's CVE misses are
v0.1 matcher artifacts (see "Every miss"). It is being re-tested on v0.2, whose matcher fixes
those. The ceiling write-up is a separate roadmap item.

## Consistency

- **cerebras is deterministic.** All 81 (case, level) groups are byte-identical across the 3 runs
  (temperature 0). For this model, k = 3 is one sample repeated, so any-of-k = all-of-k carries no
  information.
- **groq varies.** Only 10 of 81 groups are identical. Its any-of-k vs all-of-k gap (up to 6 bugs at
  L2) is a real consistency gap.

## The cursor case (L0 → L2)

`py-0017-cursor-pagination-skips`, the non-unique sort key the Groq prototype missed in 0/3 runs:
- cerebras caught it 3/3 at every level;
- groq caught it 2/3 at L0 and 1/3 at L1 and L2.

The related schema at L2 didn't help either model. With n = 3 runs, nothing here is significant.

**Most of groq's CVE misses are ground-truth and matcher problems, not reviewer misses.** The CVE
batch 1 bug ranges are too narrow for reversed-fix diffs, which span several lines and sometimes two
call sites (RISKS §5). They're left as scored. The fix is the v0.2 defect-check matcher, plus wider
or multiple ranges per bug (an idea in the roadmap).

## Precision and false positives: not measured

- **0 findings have a human verdict.** The reports print "not measured" for precision, correctly
  (RISKS §1).
- groq's "3/12 control runs with a false positive" at L0 and L1 rests on 6 *rule* verdicts. It is a
  lower bound, not a rate.
- cerebras has 0 verdicts. Its "0/12" means no finding was judged, not that none were wrong.
- Two controls have unjudged findings that read like real issues: py-0021 ("negative quantities
  accepted") and py-0022 ("empty WEBHOOK_SECRET accepted"). If confirmed, they belong in
  `known_issues`, not in the false-positive count.

## Caveats that apply (from RISKS.md)

1. **Precision unmeasured** (§1): nothing on this page says anything about noise.
2. **n is small** (§2): 23 bugs and 12 control runs. The paired qwen-vs-gpt-oss difference above
   is the only one shown, and it is preliminary until v0.2 confirms it.
3. **LLM-written cases** (§3): 22 of 27 v0.1 cases are synthetic, so recall on them may not transfer
   to real bugs. Synthetic and real (CVE) cases aren't reported separately yet.
4. **Contamination** (§4): the 5 CVE cases are public, with fixes in training data. There's no
   held-out comparison yet.
5. **Crude matcher** (§5): see "Every miss". It cuts both ways.
6. **Unstable free-tier models** (§6): results record the served model id, but providers can change
   what is behind a name.
7. **One prompt** (§7).
